# CS 255 – DriverPass Project

This repository contains my **Business Requirements Document** (Project One) and **System Design Document** (Project Two) for the DriverPass project in CS 255: System Analysis and Design.

## Reflection

**Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design?**

The client was DriverPass, a company founded by Liam that wanted to fill a gap in driver training. Many students were failing their DMV driving tests because they lacked good preparation resources. DriverPass wanted a system that offered online classes and practice tests, plus on-the-road training with an instructor. Customers needed to be able to register, choose a training package, and schedule, modify, or cancel driving lessons. The system also had to be accessible online and offline, run in the cloud so the company did not have to manage backups and security itself, support role-based access for employees, and stay current with DMV rule and policy updates.

**What did you do particularly well?**

I think I did well at turning the interview transcript into clear, specific requirements. In the business requirements document, I separated functional requirements from nonfunctional requirements and organized them by category (performance, platform, accuracy, adaptability, and security), which made the system's expectations easy to follow. In the system design document, my UML diagrams (use case, activity, sequence, and class diagrams) connected closely to the requirements, so each design element traced back to something the client actually asked for.
